# Playbook: expo-ui

Expo Router screens, Uniwind, DESIGN.md, visual / a11y polish on `apps/app`.

## Skills to load

1. `apps/app/DESIGN.md` (governing look)
2. `uniwind`
3. Then as needed: `baseline-ui`, `frontend-ui-engineering`, `improve-ui` (read-only plans), or
   accessibility skills — always subordinate to DESIGN.md and Uniwind on shared RN screens

## Recipes

- `apps/app/AGENTS.md`
- Starlight **Agent skills** → UI skill overrides (no DOM-only kits on shared screens)

## Subagents

Allowed: explore of `components/` vs a single route family; interface-review style Subagent when
the human asks for a change review.  
Not allowed: Subagent inventing a second design system or committing generated churn unrelated to
the UI change.

## Done when

UI matches DESIGN.md tokens/primitives, typechecks, and web + native behavior stay aligned where
the change touches shared components.
